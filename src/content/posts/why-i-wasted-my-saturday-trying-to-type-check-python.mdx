## How does type checking even work?

Type checkers analyze your program without running it. To do that, I first needed something called an Abstract Syntax Tree (AST), a tree where each node is an expression of value.

<img src={astImg.src} alt="Abstract Syntax Tree" width="700" />

Okay, if you're like me, I had no clue what I was looking at when I saw it for the first time.
But, one analogy which helped was thinking of a AST an a representation of grammatical structure. Say you have an sentence: "The cat sat on the mat".

You have the sentence

You have the subject "Cat"

You have the verb "sat"

You have the destination "mat"

The english language can be represented as a grammar tree!

Like diagramming a sentence. "The cat sat on the mat" becomes a tree with "sat" as root, "cat" as subject, "mat" as location. Same thing but for code. 
Did you know that all programming languages are grammar composed languages? Look it up! It's called [*Context Free Grammar*](https://en.wikipedia.org/wiki/Context-free_grammar)

With that, I learned that Python has a built-in AST module, which I could use. This honestly made the problem even tractable because otherwise
I would have to build a regex tokenizer and parser, which even with Flex and BSON would near impossible.

## Tying it in: Data flow analysis and control flow graphs

Okay he's just throwing words around now 😂

So what are these things?

I kept seeing these terms around and got annoyed of not knowing them, but turns out their crazy intuitive!

*Lets visualise why we might need a graph*

<img src={dataFlowImg.src} alt="Data flow analysis" width="700" />


As we saw, depending on the branch that executes, `y` has either value 2 or 3. 
We also need to *remember* what the type was before and after the branch, this is where we need to *flow* the data through the graph like we're actually running the program!

Woah, so do most compilers and type systems maintain some sort of internal graph? Yes they do! It's what is primary used for optimizations and typing statically. 
However, I thought that I could do away with the CFG for now and simply recurse on the AST. Well we'll see how well that goes...


### How Do We Actually Retain Type Information? 

The next step is: When traversing the AST/graph, what actual data structure should I use to store the type information?

Think about it - I needed to persist a key-value pair of symbol-to-type. What does this point to naturally?
A hash table! Or more accurately a **stack** of hash tables. 

<img src={symbolTableImg.src} alt="Data flow analysis" width="700" />

Why a stack? As we move through functions for instance, there could be two `x` active at once, a local `x`
and a global `x`. This means that its not enough to have one table, we need a hierachy of tables that mimic a lexical environmetn

## What do modern type checkers do?

After banging out a basic typing script for simple Python code, I looked up [Sorbet](https://sorbet.org/), a Ruby type checker built at Stripe. They took a language arguably more dynamic than Python and got meaningful type checking out of it.

Then TypeScript. Its type system is Turing-complete. You can write programs in the types themselves. Genius or cursed? Not sure, but it works!

## MyPy already exists though

This is where I felt dumb. MyPy, Pyright, Pyre... years of engineering already done. But after a bunch of research I noticed none of them solved what actually bugged me: type *provenance*.

I don't just want to know a function returns `Dict[str, Any]`. I want to know *where* that type came from. Base class three levels deep? Metaclass? Decorator that mutated the return type?

## Where I ended up

After doing a little bit of research and reading, I spent most of the Saturday getting an AST parser working, wrote a basic scope resolver, then immediately got stuck on decorators that modify return types. By evening I had something that could type check `x = 1 + 2` and tell you `x` is an `int`. Revolutionary.

Then I read MyPy. MyPy has been in development since 2012. 100k+ lines of code. And I thought I'd build something useful in an afternoon because Langchain annoyed me.

I did learn a lot about how type systems work though. And I still think there's something to the provenance idea?  Maybe when I have more than one Saturday.
