## How does type checking even work?

Type checkers analyze your program without running it. To do that, you first need something called an Abstract Syntax Tree (AST), a tree where each node is an expression of value

<img src={astImg.src} alt="Abstract Syntax Tree" width="700" />

Okay, if you're like me, I had no clude what I was looking at when I saw it for the first time.
But, one analogy which helped was thinking of a AST an a representation of grammatical structure. Say you have an sentence: "The cat sat on the mat".

You have the sentence

You have the subject "Cat"

You have the verb "sat"

You have the destination "mat"

The english language can be represented as a grammar tree!

Like diagramming a sentence. "The cat sat on the mat" becomes a tree with "sat" as root, "cat" as subject, "mat" as location. Same thing but for code. 
Did you know that all programming languages are grammar composed languages? Look it up! It's called context free grammar (add a link to a internet page abt cfg and italicize CFG)

## Tying it in: Data flow analysis and control flow graphs

Okay he's just throwing words around now 😂

So what are these things?

**Data flow** is tracking where values come from and where they end up. Variable `x` gets assigned here, passed into this function, returned from that one. **Control flow** is tracking which paths your code can take. Every if/else, loop, early return creates a branch. 
*Lets visualise why we might need a graph*

<img src={dataFlowImg.src} alt="Data flow analysis" width="700" />


As we saw, depending on the branch that executes, `y` has either value 2 or 3. And this applies too if y is `int` in one branch and `str` in another branch.
We also need to *remember* what the type was before and after the branch, this is where we need to *flow* the data through the graph like we're actually running the program!

Woah, so do most compilers and type systems maintain some sort of internal graph? Yes they do! It's what is primary used for optimizations and typing statically

### Quick Recap

So what do we need to to actually type check a program? 

First we need to understand WHAT the language is -> that's where our AST comes in. Representating a language with a tree. <br/>
Then we need to analyze the program, and model its execution flow -> this is our control flow graph of *all path* a program can take. <br/>
And finally we do data flow analys -> we use that graph to propagate relationships and mutations of symbols coherently throughout the program.

> Of couse, modern type checkers are wayyyy more complex than this, but this is the foundation layer 



### How Do We Actually Retain Type Information? 

What actual data structure do we use to store the types as we move through a program?

Think about it - we need to persist a key-value pair of symbol-to-type. What does this point to naturally?
A hash table! Or more accurately a **stack** of hash tables. 

<img src={symbolTableImg.src} alt="Data flow analysis" width="700" />

Why a stack? As we move through functions for instance, there could be two `x` active at once, a local `x`
and a global `x`. This means that its not enough to have one table, we need a hierachy of tables that mimic a lexical environmetn

## MyPy already exists though

This is where I felt dumb. MyPy, Pyright, Pyre... years of engineering already done. But after a bunch of research I noticed none of them solved what actually bugged me: type *provenance*.

I don't just want to know a function returns `Dict[str, Any]`. I want to know *where* that type came from. Base class three levels deep? Metaclass? Decorator that mutated the return type?

## Where I ended up

Spent most of the Saturday getting an AST parser working, wrote a basic scope resolver, then immediately got stuck on decorators that modify return types. By evening I had something that could type check `x = 1 + 2` and tell you `x` is an `int`. Revolutionary.

MyPy has been in development since 2012. 100k+ lines of code. And I thought I'd build something useful in an afternoon because Langchain annoyed me.

I did learn a lot about how type systems work though. And I still think there's something to the provenance idea?  Maybe when I have more than one Saturday.
